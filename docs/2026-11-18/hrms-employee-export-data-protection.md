# Employee Export Data-Protection Review

## Purpose
Define safeguards for employee data exports generated by HR or administrators.

## Data minimization
- Export only fields required for the stated business purpose.
- Exclude password hashes, authentication tokens, internal secrets, and unnecessary personal identifiers.
- Apply the same employee visibility rules used by the interactive application.
- Avoid exporting inactive or archived records unless explicitly required.

## Authorization and accountability
- Require an authenticated ADMIN or explicitly authorized HR role.
- Record requester, timestamp, filters, selected columns, row count, and outcome.
- Enforce authorization on the server; never trust a browser-supplied role or employee identifier.
- Prevent EMPLOYEE users from exporting other employees' records.

## File handling
- Use a short-lived download response rather than a public permanent file.
- Use safe filenames and neutralize spreadsheet formula prefixes in untrusted cell values.
- Apply size limits and pagination or asynchronous processing for large exports.
- Do not log exported row contents.

## Verification scenarios
1. ADMIN can export permitted employee fields.
2. HR can export only fields within its assigned scope.
3. EMPLOYEE cannot access the endpoint or retrieve peers by changing filters.
4. Formula-like values are emitted as inert text.
5. Failures do not expose SQL, stack traces, or filesystem paths.

## Release evidence
Attach endpoint tests, authorization results, a redacted sample export, and confirmation that sensitive fields are excluded.
